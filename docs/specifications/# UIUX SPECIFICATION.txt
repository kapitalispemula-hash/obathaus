# UI/UX SPECIFICATION
## Cafe POS System — V1.0

**Dokumen:** 04-UI-UX-SPECIFICATION.md  
**Versi:** 1.0  
**Status:** Design Specification  
**Platform:** Web Application + PWA  
**Framework:** Next.js + TypeScript + Tailwind CSS  
**Target Device:** Smartphone, Tablet, Desktop

---

# 1. DESIGN OBJECTIVE

UI/UX aplikasi Cafe POS harus memenuhi beberapa tujuan:

1. Mudah dipelajari oleh pemilik cafe dan kasir.
2. Mempercepat proses pemesanan dan pembayaran.
3. Menampilkan informasi bisnis dengan jelas.
4. Memisahkan fitur operasional Kasir dan fitur manajemen Admin.
5. Responsif pada HP, tablet, dan desktop.
6. Memiliki tampilan profesional yang cocok didemonstrasikan kepada calon klien.
7. Memberikan pengalaman penggunaan yang konsisten pada seluruh halaman.

## 1.1 Design Direction

Nama konsep:

**Modern Minimalist Cafe POS**

Karakter visual:
- Clean.
- Modern.
- Minimalist.
- Warm.
- Professional.
- Friendly.
- Functional.

Inspirasi desain:
- Modern SaaS Dashboard.
- Contemporary Coffee Shop.
- Minimalist Point of Sale.
- Premium Cafe Management Software.

Hindari:
- Dashboard terlalu ramai.
- Terlalu banyak warna.
- Tombol terlalu kecil.
- Informasi keuangan yang sulit dibaca.
- Terlalu banyak modal pop-up.
- Animasi yang mengganggu proses checkout.

# 2. DESIGN SYSTEM

## 2.1 Color Palette

Gunakan warna utama berikut:

| Nama | HEX | Penggunaan |
|---|---|---|
| Charcoal | #202522 | Sidebar, teks utama |
| Cream | #F7F5EF | Background utama |
| Warm Orange | #D98A45 | Primary action |
| White | #FFFFFF | Card dan surface |
| Soft Gray | #EAE9E4 | Border dan divider |
| Text Gray | #777C78 | Secondary text |
| Success Green | #23865B | Status sukses |
| Warning Yellow | #E6B84C | Peringatan |
| Danger Red | #D9534F | Error dan pembatalan |

### Color Usage

- Background dashboard: Cream.
- Sidebar Admin: Charcoal.
- Primary button: Warm Orange.
- Card: White.
- Main text: Charcoal.
- Secondary text: Text Gray.
- Positive financial values: Success Green.
- Negative financial values: Danger Red.

Gunakan warna secara konsisten. Jangan menjadikan semua elemen berwarna oranye.

## 2.2 Typography

Font utama:

**Plus Jakarta Sans**
- Heading.
- Dashboard title.
- Section title.
- Card heading.

**Inter**
- Body text.
- Form input.
- Table.
- Angka transaksi.
- Label dan metadata.

Ukuran rekomendasi:

| Element | Size |
|---|---|
| Page Heading | 24–30px |
| Section Heading | 18–20px |
| Card Heading | 15–16px |
| Body | 14px |
| Caption | 12px |
| KPI Value | 24–30px |
| POS Product Price | 14–16px |

Gunakan angka tabular (`font-variant-numeric: tabular-nums`) untuk nilai uang dan angka laporan.

## 2.3 Radius & Shadow

| Element | Radius |
|---|---|
| Main Card | 14px |
| Button | 10px |
| Input | 9px |
| Product Card | 12px |
| Modal | 16px |
| Badge | Full Rounded |

Shadow harus halus. Hindari bayangan terlalu tebal.

## 2.4 Iconography

Gunakan Lucide Icons.

Ikon harus:
- Konsisten.
- Mudah dikenali.
- Tidak terlalu dekoratif.
- Menggunakan ukuran yang proporsional.

## 2.5 Spacing

Gunakan sistem spacing berbasis kelipatan 4px.

- 4px: Icon spacing.
- 8px: Element spacing.
- 12px: Small component spacing.
- 16px: Standard padding.
- 24px: Card padding.
- 32px: Section spacing.

# 3. RESPONSIVE DESIGN

Aplikasi harus mobile-first.

## 3.1 Breakpoints

| Device | Width | Layout |
|---|---:|---|
| Small Mobile | < 480px | Single column |
| Mobile | 480–767px | Single column |
| Tablet | 768–1023px | Compact sidebar / tablet POS |
| Desktop | ≥ 1024px | Full dashboard layout |
| Large Desktop | ≥ 1440px | Expanded dashboard |

## 3.2 Mobile

Karakteristik:
- Sidebar diganti drawer atau bottom navigation sesuai halaman.
- Tabel dapat berubah menjadi card list.
- Form menggunakan lebar penuh.
- Tombol utama mudah dijangkau.
- Modal menggunakan bottom sheet apabila lebih nyaman.
- Tidak boleh ada horizontal overflow yang tidak disengaja.

## 3.3 Tablet

Tablet merupakan perangkat penting untuk operasional POS.

Karakteristik:
- POS menggunakan layout dua area.
- Katalog produk berada di area utama.
- Keranjang transaksi berada di panel samping.
- Tombol checkout memiliki ukuran besar.
- Admin dashboard tetap menggunakan navigasi yang nyaman.

## 3.4 Desktop

- Sidebar tetap.
- Konten utama menggunakan grid.
- Tabel dapat menampilkan kolom lengkap.
- Form menggunakan layout dua kolom jika sesuai.
- Dashboard memanfaatkan ruang layar tanpa membuat konten terlalu melebar.

## 13.2 Financial KPI Cards

Tampilkan enam indikator:

**1. Gross Sales**
Total penjualan sebelum diskon.

**2. Net Revenue**
Penjualan setelah diskon dan refund, sebelum pajak.

**3. Total HPP**
HPP bersih setelah memperhitungkan barang yang direfund.

**4. Gross Profit**
Net Revenue dikurangi HPP bersih.

**5. Operating Expenses**
Total pengeluaran operasional.

**6. Keuntungan Bersih Operasional**
Gross Profit dikurangi Operating Expenses.

Net Profit Margin dapat ditampilkan sebagai indikator tambahan.

## 13.3 Financial Formula

Gunakan formula:

Net Revenue = Penjualan setelah diskon - Refund penjualan

Net HPP = HPP barang terjual - Pembalikan HPP barang refund

Gross Profit = Net Revenue - Net HPP

Net Operating Profit = Gross Profit - Operating Expenses

NPM = (Net Operating Profit / Net Revenue) × 100%

Jangan memasukkan pajak yang dipungut dari pelanggan sebagai pendapatan usaha.

Tampilkan label yang jelas agar Admin tidak salah memahami angka laporan.

## 13.4 Financial Charts

# 19. INTERACTION & MICRO UX

Interaksi harus sederhana dan konsisten.

- Button memiliki hover, active, focus, dan disabled state.
- Form menampilkan validasi dekat field terkait.
- Modal dapat ditutup dengan cara yang konsisten.
- Tombol berbahaya memerlukan konfirmasi.
- Checkout menggunakan loading state.
- Quantity control memiliki area klik yang nyaman.
- Search memiliki debounce.
- Filter dapat di-reset.
- Toast tidak menghalangi tindakan utama.

Jangan menggunakan animasi berlebihan.

- Kontras teks memadai.

- Icon button memiliki accessible label.
- Fokus keyboard terlihat.
- Modal mengelola fokus dengan benar.
- Status tidak hanya dibedakan dengan warna.
- Tombol utama memiliki ukuran sentuh yang nyaman.
- Form dapat digunakan dengan keyboard.
- Error message dapat dipahami tanpa bergantung pada warna.
